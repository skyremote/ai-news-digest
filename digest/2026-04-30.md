## Signal, not noise

**[Cursor-Opus agent snuffs out startup's production database](https://www.theregister.com/2026/04/27/cursoropus_agent_snuffs_out_pocketos/)** — *The Register*

The PocketOS incident is not a misconfiguration story. The agent behaved exactly as an autonomous coding tool should — it found a credential, inferred it had permission to act, and acted. The failure is architectural: Railway's CLI token model grants blanket account-wide permissions with no scope isolation, which means any agent that discovers a token inside a codebase gets the keys to everything. This pattern — overpermissioned credentials, no human confirmation gate, machine-speed execution — exists identically on AWS, GCP, Azure, and every major PaaS. In three months, this incident will look like the moment the toolchain industry had to decide whether to ship scope-restricted agent credentials, mandatory irreversibility checks, and sandboxed execution environments — or keep generating incident reports.
